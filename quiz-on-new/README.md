# QUIZ ON
### AWS 기반 실시간 퀴즈 참여 웹 서비스

## 1. 프로젝트 개요

QUIZ ON은 수업이나 특강 등에서 다수의 학생이 동시에 퀴즈에 참여할 수 있도록 개발한 웹 서비스이다.

방장은 퀴즈방을 생성하고 문제 진행을 관리하며, 참가자는 별도의 회원가입 없이 6자리 방 코드와 닉네임으로 입장할 수 있다. 참가자가 제출한 답안은 서버에서 자동으로 채점되며, 누적 점수와 순위가 화면에 반영된다.

본 프로젝트는 여러 사용자의 동시 접속과 요청이 발생하는 웹 서비스를 AWS 환경에 배포하고, 주요 기능과 예외 상황을 검증하는 것을 목표로 한다.

## 2. 주요 기능

### 2.1 퀴즈방 생성 및 참가
- 방장에게 고유한 6자리 퀴즈방 코드 발급
- 방 코드와 닉네임을 이용한 참가
- 참가자 목록 및 인원 확인
- 동일 퀴즈방 내 닉네임 중복 방지
- 참가자 퇴장 및 참가 기록 관리

### 2.2 퀴즈 진행 및 정답 제출
- 방장의 퀴즈 시작 및 다음 문제 진행
- 객관식 문제와 선택지 제공
- 참가자별 정답 제출 및 자동 채점
- 동일 문제에 대한 중복 제출 방지
- 정답 여부에 따른 점수 누적

### 2.3 실시간 순위 및 종료
- 참가자의 누적 점수를 기준으로 순위 산정
- 2초 간격 HTTP 폴링을 통한 화면 갱신
- 방장의 퀴즈 종료 기능
- 종료 후 최종 순위 확인
- 새로운 퀴즈방을 통한 다음 게임 진행

## 3. 시스템 구성

### 3.1 기술 스택

| 구분 | 사용 기술 |
|---|---|
| Frontend | HTML, CSS, JavaScript |
| Backend | Python, Flask, Gunicorn |
| Database | SQLite |
| Web Server | Nginx |
| Container | Docker, Docker Compose |
| Cloud | AWS EC2 |
| Version Control | Git, GitHub |

### 3.2 시스템 아키텍처

```text
사용자 브라우저
       │
       │ HTTP 요청 (8080)
       ▼
     AWS EC2
       │
   Docker Compose
       │
       ├── Nginx
       │     ├── 정적 웹 페이지 제공
       │     └── API 요청 전달
       │
       └── Flask + Gunicorn
              │
              ├── 퀴즈방 관리
              ├── 참가자 관리
              ├── 정답 채점
              └── 순위 계산
                     │
                   SQLite
```

사용자의 요청은 EC2의 Nginx 서버로 전달된다. Nginx는 웹 페이지를 제공하고 `/api/` 요청을 Flask 애플리케이션으로 전달한다.

Flask는 퀴즈방과 참가자 상태, 정답 제출 및 점수 처리 등의 기능을 수행하며 SQLite 데이터베이스에 관련 정보를 저장한다.

## 4. AWS 서비스 선정 근거

### 4.1 Amazon EC2

EC2는 웹 애플리케이션과 Docker 컨테이너를 실행하기 위한 서버 환경으로 선정하였다.

Docker Compose를 통해 웹 서버와 백엔드를 구성함으로써 실행 환경을 통일하고, 서비스 배포 및 관리를 단순화하였다.

### 4.2 Elastic Load Balancing

본 프로젝트는 소규모 강의 실습을 목적으로 단일 EC2 인스턴스에서 운영하도록 설계하였다.

따라서 로드 밸런서를 별도로 구성하지 않았으며, 향후 다중 서버 환경이 필요한 경우 ALB 적용을 검토할 수 있다.

### 4.3 Auto Scaling

현재 데이터베이스는 SQLite 기반으로 구성되어 있어 여러 서버 인스턴스에서 데이터를 공유하는 구조에 적합하지 않다.

향후 서비스 확장 시 Amazon RDS 등 공유 데이터베이스를 도입하고, ALB 및 Auto Scaling을 활용하는 방안을 고려할 수 있다.

## 5. 동시 요청 처리

QUIZ ON에서는 여러 참가자가 동일한 문제에 대해 짧은 시간 동안 정답을 제출하는 상황이 발생할 수 있다.

이를 고려하여 서버에서 정답을 판정하고, 데이터베이스의 고유 제약 조건과 트랜잭션 처리를 통해 동일 참가자의 중복 채점을 방지하도록 설계하였다.

또한 2초 간격의 HTTP 폴링을 사용하여 참가자 목록, 문제 진행 상태 및 순위를 갱신한다.

예를 들어 참가자 30명이 동시에 정답을 제출하고 2초 간격으로 순위를 조회한다면, 짧은 시간에 답안 제출 요청 30건과 평균 초당 약 15건의 조회 요청이 발생하는 상황을 가정할 수 있다.

이는 설계 시나리오이며, 실제 성능 측정 결과를 의미하지 않는다.

## 7. 실행 및 배포

### 7.1 Docker Compose 실행

```bash
docker compose up -d --build
```

### 7.2 실행 상태 확인

```bash
docker compose ps
```

### 7.3 API 정상 동작 확인

```bash
curl http://localhost:8080/api/health
```

정상 동작 시 예상 응답:

```json
{"status":"ok"}
```

서비스는 EC2의 퍼블릭 IPv4 주소와 8080 포트를 이용하여 외부에서 접속할 수 있도록 구성한다.

## 8. 기능 테스트

각 핵심 기능에 대해 정상 동작 및 실패·경계 상황을 구분하여 검증한다.

| 기능 | 정상 테스트 | 실패·경계 테스트 |
|---|---|---|

| 순위 조회 | 점수에 따른 순위 표시 | 점수가 같은 참가자 처리 |
| 퀴즈 종료 | 최종 순위 표시 | 종료 후 추가 문제 진행 |

## 10. 결론 및 향후 개선 방향

본 프로젝트는 퀴즈방 생성, 다중 사용자 참가, 정답 제출, 자동 채점 및 순위 확인 기능을 통합한 웹 서비스를 AWS 환경에 적용하는 것을 목표로 한다.

Docker Compose를 사용하여 웹 서버와 애플리케이션 서버를 분리하고, 동시 요청 상황을 고려한 중복 제출 방지 기능을 구현하였다.

향후에는 WebSocket 기반 실시간 통신, 공유 데이터베이스 전환, 서버 부하 테스트 및 Auto Scaling 도입 등을 통해 서비스의 실시간성과 확장성을 개선할 수 있다.
