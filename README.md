# QUIZ ON

### 함께 풀고, 바로 확인하는 실시간 퀴즈 플랫폼

QUIZ ON은 퀴즈를 직접 제작하고, 방 코드를 공유해 여러 사람이 함께 문제를 풀며 점수를 경쟁할 수 있는 웹서비스입니다. 별도의 회원가입 없이 수업, 스터디, 동아리 활동 등에서 간편하게 활용할 수 있습니다.

> **프로젝트 상태**  
> 로컬 Docker Compose 실행을 위한 코드가 준비되어 있습니다. **AWS 배포 및 배포 주소에서의 기능 검증은 아직 완료되지 않았습니다.** 아래의 ‘검증 결과’ 및 ‘제출 정보’는 실제 실행 후 기입해야 합니다.

## 1. 서비스 소개

**대상 사용자:** 수업·특강 진행자, 스터디 리더, 퀴즈에 함께 참여하려는 학생과 일반 사용자

**이용 상황:** 수업이나 행사가 시작되면 참가자들이 같은 시간에 퀴즈방으로 접속하고 답안을 제출합니다. 여러 요청이 짧은 시간에 집중되는 상황을 가정해, 참여·채점·점수 반영이 서버에서 일관되게 처리되도록 구성했습니다.

**주요 기능은 3가지입니다.**

| 주요 기능 | 사용자에게 제공하는 기능 | 확인할 수 있는 결과 |
| --- | --- | --- |
| **① 퀴즈 제작 및 관리** | 퀴즈 세트 생성·조회·수정·삭제, 문제·보기·정답 입력 | 제작한 퀴즈가 목록에 나타나고 방 생성 시 선택 가능 |
| **② 퀴즈방 생성 및 참가 관리** | 퀴즈 선택, 6자리 방 코드 발급, 닉네임 입장, 방 나가기 | 참가 인원과 참가자 목록이 함께 갱신 |
| **③ 퀴즈 대결 및 결과 확인** | 방장 진행, 답안 제출, 자동 채점, 점수·순위 갱신, 종료 | 문제별 점수가 누적되고 최종 순위 표시 |

## 2. 사용 방법

### ① 나만의 퀴즈 만들기

1. 메인 화면에서 **퀴즈 제작 열기**를 선택합니다.
2. 퀴즈 제목과 문제를 **2~10개** 입력합니다.
3. 문제마다 서로 다른 보기 4개를 작성하고 정답 하나를 선택합니다.
4. **새 퀴즈 저장**을 누르면 목록에 등록됩니다.
5. 내가 만든 퀴즈는 동일한 브라우저에서 수정하거나 삭제할 수 있습니다.

기본으로 제공되는 **컴퓨터공학 퀴즈 5문제**를 선택해도 됩니다. 제목·문제 길이, 빈 보기, 중복 보기, 정답 누락 등은 저장 전에 검사합니다. 다른 사용자가 제작한 퀴즈의 내용은 열람할 수 있지만 수정·삭제할 수 없습니다. 사용 중인 퀴즈 세트는 진행 중인 게임에 영향을 주지 않도록 변경이 제한됩니다.

### ② 퀴즈방 만들고 참가하기

**방장**은 진행할 퀴즈를 선택한 뒤 **새 퀴즈방 만들기**를 누릅니다. 표시된 6자리 코드를 참가자에게 공유합니다.

**참가자**는 **퀴즈 참가하기**에서 방 코드와 닉네임을 입력합니다. 같은 방에서 이미 사용 중인 닉네임은 중복 사용할 수 없으며, 시작된 방이나 종료된 방에는 새로 입장할 수 없습니다.

참가자가 **방 나가기**를 누르면 서버에서 해당 참가자의 답안과 점수 기록을 제거하고 순위에도 반영합니다. 브라우저 탭을 그냥 닫는 것만으로 자동 퇴장되지는 않습니다.

### ③ 퀴즈 대결하고 결과 확인하기

1. 참가자가 한 명 이상 입장하면 방장이 **퀴즈 시작**을 선택합니다.
2. 참가자는 각 문제에서 보기 1개를 선택해 답안을 제출합니다.
3. 서버에서 정답을 채점하고 **정답당 10점**을 누적합니다. 같은 문제에 두 번 답할 수는 없습니다.
4. 방장은 **다음 문제**로 진행하거나 **퀴즈 종료**를 선택할 수 있습니다.
5. 모든 문제를 마치거나 방장이 종료하면 최종 순위를 확인할 수 있습니다.

순위·제출 인원 등의 화면 정보는 **2초 간격 HTTP 요청(폴링)**으로 갱신됩니다. WebSocket을 사용한 즉시 푸시 방식은 아닙니다. 종료된 방의 결과를 보고 새 퀴즈를 진행하려면 새로운 방을 만들 수 있습니다.

## 4. 시스템 구성도 및 요청 경로

```text
[사용자 브라우저: 방장 / 참가자]
                |
         HTTP :8080
                |
        [AWS EC2 예정]
                |
        [Docker Compose]
                |
         [Nginx :80]
          /          \
  정적 화면 제공    /api/* 요청 전달
                       |
              [Flask/Gunicorn :5000]
                       |
                 [SQLite DB]
                       |
              [Docker 볼륨 quizdata]
```

- **화면 요청:** 브라우저 → Nginx → HTML/CSS/JavaScript 응답
- **기능 요청:** 브라우저 → Nginx(`/api/*`) → Flask API → SQLite → JSON 응답 → 화면 갱신
- **데이터 유지:** SQLite 파일은 Docker 볼륨에 보관되어 컨테이너 재생성 후에도 유지될 수 있습니다. `docker compose down -v` 명령을 사용하면 해당 볼륨이 삭제될 수 있으므로 주의하세요.

## 5. 로컬 실행 안내

### 사전 준비

- Docker Desktop 또는 Docker Engine + Compose 플러그인
- 소스코드를 내려받을 수 있는 Git(선택)
- 사용 가능한 **8080 포트**

### 실행

프로젝트의 `docker-compose.yml`이 있는 위치에서 다음 명령어를 실행합니다.

```powershell
docker compose config
docker compose up -d --build
docker compose ps
```

브라우저에서 **http://localhost:8080**에 접속합니다.

서버 상태는 다음 명령어로 확인할 수 있습니다.

```powershell
Invoke-RestMethod http://localhost:8080/api/health
```

정상 응답 예시:

```json
{"status":"ok"}
```

### 문제 해결 및 종료

```powershell
# 실행 로그 확인
docker compose logs --tail=80

# 코드 수정 후 다시 빌드
docker compose up -d --build

# 컨테이너 중지(데이터 볼륨 유지)
docker compose down
```

8080 포트가 이미 사용 중이라면 해당 프로그램을 종료하거나 Compose 포트를 변경해야 합니다. 패키지 설치 중 `CERTIFICATE_VERIFY_FAILED`가 나타나면 네트워크·프록시 인증서 신뢰 설정을 점검하세요. 인증서 검증을 비활성화하는 설정은 배포 환경에 사용하지 않습니다.

## 8. AWS 배포 계획 및 서비스 선택 근거

> 이 절은 **예정된 배포 구성**입니다. 실제 실행을 완료한 후 인스턴스 정보와 접속 주소 및 검증 결과를 추가하세요.

### AWS 서비스 선택

- **EC2:** Docker Compose 기반 웹서비스를 가상 서버에서 실행하기 위해 선택
- **ELB(ALB): 미적용 예정.** 소규모 단일 서버 과제에서는 로드 밸런서의 추가 운영 비용 및 구성 복잡도가 커, 우선 단일 EC2로 구성
- **EC2 Auto Scaling: 미적용 예정.** 단일 인스턴스 시연 범위에서는 자동 증설보다 기능 검증과 비용 통제가 우선
- **향후 확장:** 동시 사용자가 증가하면 공유 데이터베이스(RDS 등)로 이전하고 ALB·Auto Scaling을 검토. 현재 SQLite 데이터 파일 구조는 여러 서버에 그대로 복제해 확장하기에 적합하지 않음

### 요청 집중 시나리오 및 비용 고려

수업 시작 직후 **30명이 같은 퀴즈에 접속**한다고 가정합니다. 30명이 거의 동시에 답을 제출하면 쓰기 요청이 집중됩니다. 각 사용자의 화면이 2초마다 상태를 조회하므로, 30명 기준 **평균 약 15회/초의 상태 조회 요청**이 발생할 수 있습니다. 이는 설계상 계산값이며 측정된 부하 시험 결과가 아닙니다.

실습에서는 서버 인스턴스 수를 1대로 제한하고 불필요한 AWS 서비스 사용을 줄입니다. 배포 후 실제 비용은 AWS 요금과 사용 시간에 따라 달라집니다. 검사 종료 이후에는 필요한 데이터를 보존한 뒤 불필요한 AWS 자원을 정리합니다.

### 배포 및 확인 순서

1. Ubuntu 기반 EC2 인스턴스를 생성하고 공인 IP를 확인합니다.
2. 보안 그룹에서 **SSH 22는 관리자 IP로 제한**, 서비스 포트 **8080은 검사에 필요한 접속 범위로 제한**합니다.
3. EC2에 Docker 및 Compose 플러그인을 설치합니다.
4. GitHub 저장소에서 코드를 내려받습니다.
5. 프로젝트 디렉터리에서 `docker compose up -d --build`로 실행합니다.
6. `docker compose ps`, `/api/health` 및 실제 브라우저 접속을 확인합니다.
7. 배포 주소에서 **3개 주요 기능 각각의 정상·실패 사례**를 재검증하고 결과를 기록합니다.
