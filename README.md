# QUIZ ON — 클라우드 컴퓨팅 과제 (3대 핵심 기능)

> 과제 시연을 위한 소규모 웹서비스. **AWS 배포는 아직 수행되지 않았으며**, 아래의 EC2 절차는 향후 배포 계획입니다. 로컬 기능도 사용자 PC에서 검증해야 합니다.

## 1. 서비스 설명과 대상 사용자

수업·특강 시작 직후 학생들이 동시에 접속하여 문제를 푸는 상황을 가정합니다. 사용자(교수자·학생)가 직접 퀴즈를 만들어 공유하고, 방 코드로 모여 대결하는 서비스입니다.

**핵심 기능 3개**

1. **사용자 맞춤형 퀴즈 제작·관리**: 제목과 2~10개 문제(문제, 보기 4개, 정답)를 입력하여 퀴즈 세트를 생성·조회·수정·삭제합니다. 정답 누락이나 중복 보기는 오류로 막습니다. 만든 브라우저의 토큰으로 수정·삭제 권한을 확인합니다.
2. **퀴즈방 생성·참가 관리**: 기본 퀴즈 또는 저장된 퀴즈를 선택하여 6자리 코드의 방을 만들고, 참가자는 닉네임을 사용해 입장합니다. 중복 닉네임과 진행 중 입장을 차단합니다. 참가자가 `방 나가기`를 누르면 참가자·답안·점수 기록이 삭제됩니다.
3. **퀴즈 대결·채점·결과 관리**: 방장이 시작·다음 문제·종료를 제어합니다. 참가자는 문제당 1회 답안을 제출하고 자동 채점됩니다(정답당 10점). 실시간에 가까운 순위는 **2초 HTTP 폴링**으로 갱신하며, 종료 후 최종 순위를 보여 줍니다.

### 기술
- 프런트엔드: HTML, CSS, JavaScript (별도 빌드 불필요)
- 웹 서버/리버스 프록시: Nginx
- 백엔드: Flask + Gunicorn
- 데이터 저장: SQLite(영속 Docker 볼륨), 트랜잭션으로 중복 점수 방지
- 컨테이너: Docker Compose

## 2. 아키텍처/요청 경로

```text
브라우저 (방장 및 참가자)
    │ HTTP :8080
    ▼
Nginx 컨테이너 (:80)
    ├── /             → 정적 웹 화면
    └── /api/*        → Flask/Gunicorn 컨테이너 (:5000)
                                  └── SQLite (/data/quiz.db)
                                      Docker 볼륨: quizdata
```

**AWS 배포 시** 동일한 Compose 구성을 EC2에 올릴 계획입니다. 보안 그룹에서는 8080 포트를 검사자 IP로 제한하고 SSH 22 포트를 관리자 IP로 제한합니다. 실제 배포가 완료되면 인스턴스 종류·실제 URL·성공 기록을 채워야 합니다.

**ELB(ALB)·Auto Scaling 검토:** 이번 실습은 단일 EC2에서 Docker Compose를 활용하는 소규모 서비스이므로 추가 비용 및 관리 복잡도를 고려해 둘 다 미적용 예정입니다. 현재 SQLite 파일은 여러 앱 서버가 동시에 공유하기에 부적합하므로, 확장할 경우 RDS 같은 공유 DB로 옮긴 뒤 ALB/Auto Scaling을 검토해야 합니다.

**동시 접속 시나리오(가정):** 학생 30명이 동시에 답안을 제출하면 순간적으로 30개 쓰기 요청이 발생하고, 학생 30명이 2초마다 상태를 조회하면 초당 약 15개 읽기 요청이 발생합니다. 이 수치는 **예상 계산**이며 실제 부하 테스트 측정값은 아닙니다.

## 4. Windows 로컬 실행

1. 기존 퀴즈온 프로젝트가 8080 포트를 사용 중이면 해당 프로젝트 폴더에서 `docker compose down` 실행(데이터 삭제 옵션 `-v`는 붙이지 않음).
2. 이 폴더에서 실행:

```powershell
cd C:\2424001\week10\quiz_on_three_features
docker compose config
docker compose up -d --build
docker compose ps
Invoke-RestMethod http://localhost:8080/api/health
```

- 화면: http://localhost:8080
- API 상태: `{"status":"ok"}`
- 오류 로그: `docker compose logs --tail=80`
- 빌드에서 `CERTIFICATE_VERIFY_FAILED`가 발생하면 기관 프록시 CA를 신뢰 저장소에 추가해야 합니다. `pip --trusted-host`는 TLS 확인을 약화하므로 공식 배포 이미지에는 권장하지 않습니다.

### 기존 데이터 유지 및 이전 버전 주의
- 이 프로젝트는 별도 Docker Compose 프로젝트/볼륨을 사용할 수 있습니다. 과거 데이터가 자동으로 합쳐지는 것은 아닙니다.
- 기존 `quizrush`를 덮어쓰지 말고 별도 폴더로 실행하세요.
- 기존 방 DB에서 `rooms.quiz_set_id`가 없다면 시작 시 컬럼을 추가하는 마이그레이션이 포함되어 있습니다.
- 퀴즈 세트 수정·삭제 토큰은 제작한 브라우저의 `localStorage`에 저장됩니다. 저장소가 초기화되면 수정·삭제 권한을 복구할 수 없습니다. 로그인 없는 과제용 설계입니다.
- 창을 강제로 닫았을 때 자동 퇴장 기능은 아직 없습니다. 참가자는 반드시 **방 나가기**를 눌러야 순위에서 제거됩니다.

## 6. AWS EC2 배포 절차(미실행)

1. EC2 생성(Ubuntu), 인스턴스 공인 IPv4 확인
2. 보안 그룹: SSH 22는 관리자 공인 IP, 8080은 검사자 IP로 제한
3. Docker Engine 및 Docker Compose 플러그인 설치
4. Git 저장소에서 코드 가져오기
5. `docker compose up -d --build` 실행, `docker compose ps` 확인
6. `http://<EC2_공인_IP>:8080` 접속하고 **배포 주소에서 위 3개 큰 기능 각각 정상·실패 사례 검증**
7. 테스트 결과·화면 캡처·버전·주소를 이 README와 LMS에 기재

AWS 배포 이후에만 **AWS 배포 완료**라고 기록할 수 있습니다.

## 8. 제한 사항

단일 SQLite 기반 데모로서 대규모 트래픽/다중 서버 운영을 검증하지 않았습니다. 서버는 2초 폴링이며 WebSocket은 없습니다. 퀴즈를 만든 브라우저에서만 수정/삭제 가능하도록 토큰을 로컬 저장하므로 사용자 계정·복구 기능이 없습니다. 문제 제작은 4지선다와 2~10문제 범위로 제한됩니다.
